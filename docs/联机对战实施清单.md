## 总体架构

### 同步模型：服务器权威 + 客户端预测

```
┌─────────────┐         ┌─────────────┐         ┌─────────────┐
│  Client A   │◄───────►│   Server    │◄───────►│  Client B   │
│ (本地预测)   │  Input   │ (权威仿真)  │  State   │ (插值回放)   │
└─────────────┘         └─────────────┘         └─────────────┘
```

- **服务器**：运行完整物理仿真（球、所有玩家移动与碰撞），是唯一权威
- **客户端**：本地玩家立即响应输入（预测），远程实体通过插值平滑显示
- **球**：仅服务器计算物理；客户端纯插值回放
- **AI 玩家**：仅服务器运行 AI 逻辑，结果作为普通状态广播

### 数据流

```
Client A 按键 → 打包 InputSnapshot → RPC 发送到 Server
Server 收到输入 → 应用到对应 Player → 物理 tick → 生成 WorldSnapshot
Server 广播 WorldSnapshot → 所有 Client
Client 收到 Snapshot → 远程实体插值 / 本地实体和解校正
```

### 同步频率

| 数据类型 | 频率 | 可靠性 | 说明 |
|---------|------|--------|------|
| 玩家输入 | 每物理帧 (60Hz) | unreliable | 客户端→服务器，丢包可容忍 |
| 世界快照 | 20Hz (每3物理帧) | unreliable | 服务器→客户端，位置/速度/状态 |
| 关键事件 | 即时 | reliable | 射门、传球、进球、状态切换等 |
| 游戏状态 | 即时 | reliable | GameManager 状态机转换 |

## 核心数据结构

### InputSnapshot（客户端→服务器）

```gdscript
# 每帧客户端发送的输入快照
var input_snapshot := {
    "tick": int,              # 客户端物理帧序号
    "direction": Vector2,     # 移动方向 (get_input_vector 结果)
    "shoot_pressed": bool,    # 射门键按下
    "shoot_released": bool,   # 射门键释放
    "pass_pressed": bool,     # 传球键按下
    "jump_pressed": bool,     # 跳跃组合键触发
    "shot_direction": Vector2, # 蓄力期间的瞄准方向增量
}
```

### WorldSnapshot（服务器→客户端）

```gdscript
# 服务器每 50ms 广播一次的世界状态
var world_snapshot := {
    "tick": int,                    # 服务器物理帧序号
    "time_left": float,             # 剩余时间
    "ball": {
        "position": Vector2,
        "velocity": Vector2,
        "height": float,
        "height_velocity": float,
        "state": int,               # Ball.State 枚举值
        "carrier_index": int,       # 持球者索引 (-1=无人)
    },
    "players": [                    # 12个玩家 (home 0-5, away 6-11)
        {
            "position": Vector2,
            "velocity": Vector2,
            "heading": Vector2,
            "height": float,
            "state": int,           # Player.State 枚举值
            "hp": float,
        },
        # ...
    ],
}
```

### EventRPC（可靠事件）

```gdscript
# 关键游戏事件，reliable 传输
# 射门事件
{ "type": "shoot", "player_index": int, "direction": Vector2, "power": float, "power_shot_type": int }
# 传球事件
{ "type": "pass", "player_index": int, "destination": Vector2 }
# 铲球事件
{ "type": "tackle", "player_index": int }
# 进球事件
{ "type": "scored", "country_scored_on": String }
# 游戏状态切换
{ "type": "game_state", "state": int, "data": Dictionary }
```

## 阶段 1: SyncManager 核心 (1周)

### 1.1 创建 SyncManager Autoload

- [ ] 创建 `scenes/network/sync_manager.gd`
- [ ] 注册为 Autoload（`project.godot`）
- [ ] 添加 `is_online_match: bool` 标识（区分单机/联机）
- [ ] 添加 `server_tick: int` 计数器（服务器物理帧序号）
- [ ] 添加 `sync_interval: int = 3`（每3个物理帧广播一次快照 = 20Hz）

### 1.2 玩家索引系统

> 联机模式下所有 12 个玩家需要稳定的索引，用于网络引用。

- [ ] 在 `ActorsContainer` 中建立 `all_players: Array[Player]`（home 0-5, away 6-11）
- [ ] 每个 `Player` 添加 `network_index: int`（在 spawn 时赋值）
- [ ] 每个 `Player` 添加 `owner_peer_id: int`（控制该玩家的客户端 peer_id，CPU 为 -1）
- [ ] `SyncManager` 持有 `all_players` 引用和 `ball` 引用

### 1.3 输入上行（客户端→服务器）

- [ ] 客户端每物理帧 `_physics_process()` 采集本地输入为 `InputSnapshot`
- [ ] 通过 `@rpc("any_peer", "unreliable") _rpc_send_input(snapshot: Dictionary)` 发送到服务器
- [ ] 服务器端 `SyncManager` 维护 `_pending_inputs: Dictionary`（peer_id → 最新 InputSnapshot）
- [ ] 服务器在 `_physics_process()` 中消费 pending inputs，应用到对应 Player

### 1.4 世界快照下行（服务器→客户端）

- [ ] 服务器每 `sync_interval` 帧收集一次 WorldSnapshot
- [ ] 通过 `@rpc("authority", "unreliable") _rpc_broadcast_snapshot(snapshot: Dictionary)` 广播
- [ ] 客户端 `SyncManager` 接收快照，存入 `_snapshot_buffer: Array[Dictionary]`（保留最近 3 个）
- [ ] 客户端在 `_physics_process()` 中对远程实体执行插值

## 阶段 2: Player 网络化改造 (1周)

- [ ] `network_index: int = -1` — 全局唯一索引 (0-11)

- [ ] `is_local_controlled: bool` — 是否由本地玩家控制（运行时计算）

### 2.2 ControlScheme 扩展

> 现有 `ControlScheme { CPU, P1, P2 }` 不足以表达联机场景。

- [ ] `KeyUtils.ACTIONS_MAP` 中为 `ONLINE_LOCAL` 复用 P1 的按键映射
- [ ] `ONLINE_REMOTE` 不读取本地输入，由网络状态驱动

### 2.3 Player._process() 分支改造

```gdscript
# 改造后的 _process 逻辑（伪代码）
func _process(delta):
    flip_sprites()
    set_sprite_visiable()
    process_gravity(delta)
    move_and_slide()
    # 联机模式下远程玩家不执行本地物理，由快照驱动
    # 具体逻辑在 PlayerState 中通过 control_scheme 判断
```

### 2.4 PlayerStateMoving 网络适配

- [ ] `handle_human_movement()` 仅在 `ONLINE_LOCAL` / `P1` / `P2` 时执行
- [ ] 服务器端：收到客户端输入后调用 `apply_remote_input(snapshot)` 驱动 ONLINE_REMOTE 玩家
- [ ] 客户端：远程玩家的 `PlayerStateMoving` 不读取 KeyUtils，由插值位置驱动

### 2.5 关键动作 RPC 同步

> 射门、传球、铲球等离散事件必须 reliable 同步。

- [ ] **射门**：客户端蓄力释放时，发送 `{ direction, power }` 到服务器
  - 服务器验证后执行 `ball.shoot()`，广播射门事件给所有客户端
  - 客户端收到后播放射门动画和音效
- [ ] **传球**：客户端触发传球时，发送到服务器
  - 服务器执行 `ball.pass_to()`，广播传球事件
- [ ] **铲球**：客户端触发铲球时，发送到服务器
  - 服务器切换玩家状态为 TACKLING，广播状态变更
- [ ] **跳跃**：客户端触发跳跃组合键时，发送到服务器
  - 服务器切换玩家状态为 JUMPING

### 2.6 ActorsContainer 联机生成改造

- [ ] 新增 `setup_online_control_schemes()` 方法
- [ ] 根据 `GameManager.online_slot_assignments` 分配 `owner_peer_id` 和 `ControlScheme`
- [ ] 本地玩家的 slot 对应的 Player 设为 `ONLINE_LOCAL`
- [ ] 同房间其他玩家的 slot 设为 `ONLINE_REMOTE`
- [ ] 未被任何玩家占据的 slot 保持 `CPU`（仅服务器运行 AI）
- [ ] 在 `setup_control_schemes()` 中检测 `SyncManager.is_online_match` 走联机分支

### 3.2 Ball 状态同步

- [ ] 球状态切换（`switch_state`）仅服务器执行
- [ ] 服务器切换球状态时，通过 reliable RPC 广播 `{ state: int, data: Dictionary }`
- [ ] 客户端收到后调用 `switch_state()` 同步状态和动画
- [ ] `BallStateData` 添加 `to_dict()` / `from_dict()` 序列化方法

### 3.3 Ball 位置插值（客户端）

```gdscript
# 客户端 Ball 插值逻辑（在 SyncManager 或 Ball 中实现）
func apply_network_state(data: Dictionary) -> void:
    var target_pos: Vector2 = data["position"]
    var target_vel: Vector2 = data["velocity"]
    # 位置插值 + 速度外推
    position = position.lerp(target_pos, 0.4)
    velocity = target_vel
    height = lerpf(height, data["height"], 0.4)
    height_velocity = data["height_velocity"]
```

### 3.4 射门/传球 网络流程

```
[Client] 蓄力释放 → RPC _rpc_request_shoot(direction, power) → [Server]
[Server] 验证 → ball.shoot() → RPC _rpc_notify_shoot(player_idx, direction, power, type) → [All Clients]
[Client] 收到 → 播放射门动画 + 音效（球位置由快照驱动）
```

- [ ] `SyncManager` 添加 `@rpc("any_peer", "reliable") _rpc_request_shoot(direction, power)`
- [ ] `SyncManager` 添加 `@rpc("authority", "reliable") _rpc_notify_shoot(player_idx, direction, power, type)`
- [ ] 传球同理：`_rpc_request_pass()` / `_rpc_notify_pass()`

## 阶段 5: 客户端预测与和解 (1周)

### 5.1 本地玩家预测

> 本地玩家输入后立即响应，不等待服务器确认，避免操作延迟感。

- [ ] 本地玩家的 `PlayerStateMoving` 正常读取 KeyUtils 并移动（与单机一致）
- [ ] 同时将每帧输入存入 `InputBuffer`（带 tick 序号）
- [ ] 本地玩家的位置/速度由本地物理驱动，不被快照直接覆盖

### 5.2 服务器和解（Reconciliation）

- [ ] 每次收到 WorldSnapshot 时，比较服务器返回的本地玩家位置与预测位置
- [ ] 若偏差 < 阈值（如 3px）：忽略，预测正确
- [ ] 若偏差 ≥ 阈值：
  - 将本地玩家位置重置为服务器位置
  - 从该 tick 开始，重放 InputBuffer 中后续的输入
  - 平滑过渡避免跳变（lerp 到校正位置）

```gdscript
const RECONCILIATION_THRESHOLD := 3.0  # 像素

func reconcile(server_pos: Vector2, server_tick: int) -> void:
    var error := position.distance_to(server_pos)
    if error > RECONCILIATION_THRESHOLD:
        # 平滑校正而非瞬移
        position = position.lerp(server_pos, 0.5)
```

### 5.3 远程实体插值

- [ ] 创建 `SnapshotInterpolator` 类
- [ ] 维护最近 2-3 个快照的缓冲区
- [ ] 远程玩家在两个快照之间做时间插值（Entity Interpolation）
- [ ] 插值延迟 = 2 × 快照间隔（约 100ms），换取平滑度
- [ ] 球的插值同理，但插值系数可更激进（0.4-0.5）

```gdscript
# 远程实体插值（伪代码）
func interpolate_remote_player(player: Player, prev: Dictionary, next: Dictionary, t: float) -> void:
    player.position = prev["position"].lerp(next["position"], t)
    player.velocity = next["velocity"]
    player.heading = next["heading"]
```

## 阶段 8: 优化与健壮性 (1周)

### 8.1 带宽优化

- [ ] WorldSnapshot 使用增量压缩：仅发送与上一帧有变化的字段
- [ ] 静止玩家（velocity=0 且状态未变）跳过同步
- [ ] Vector2 使用 `snapped(0.1)` 降低精度减少数据量
- [ ] 考虑将 WorldSnapshot 打包为 `PackedByteArray` 替代 Dictionary

### 8.2 延迟补偿

- [ ] 服务器记录每个客户端的 RTT（通过 ping/pong）
- [ ] 铲球/碰撞判定时回溯到客户端发出输入时的服务器状态
- [ ] 可选：服务器端输入缓冲（jitter buffer）平滑不均匀到达的输入

### 8.3 断线重连（可选，后续迭代）

- [ ] 检测 `server_disconnected` 信号
- [ ] 保存最后的 WorldSnapshot
- [ ] 重连后服务器发送完整状态快照恢复
- [ ] 重连期间 AI 接管

### 8.4 作弊防护

- [ ] 服务器验证输入合法性（移动速度不超过 `speed`、射门力量不超过上限）
- [ ] 服务器验证动作前置条件（必须持球才能射门/传球）
- [ ] 限制输入频率（超过 60Hz 的输入丢弃）
